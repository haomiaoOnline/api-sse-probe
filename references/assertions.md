# 判断依据编写说明

本 Skill 使用**确定性程序断言**，不借助 AI 判断语义或自动补充同义词。

## 测试表的两列

- **判断依据（公共）**：填写基础要求，例如 `HTTP 200 / 文本回复` 或 `HTTP 200 / 衍生问题`。
- **特殊判断依据**：填写具体值，例如 `文本回复包含“暂停”或“停止”`、`title是“灵犀服务”`。
- 两列的“同上”分别继承本列上一条有效内容；所有必需条件默认按 **AND** 汇总。不要将整行设置为 `any` 来代替关键词内部 OR。

## 支持的条件

| 条件示例 | 判定方式 |
| --- | --- |
| `HTTP 200` | 实际 HTTP 状态码是 200 |
| `文本回复` | 助手 `data.text` 非空 |
| `衍生问题` / `有追问信息` | 真实 `data.questions` 含非空字符串 |
| `title` | 存在非空业务标题 |
| `skillId` | 真实业务字段有非空 skillId |
| `sdk` / `deeplink` | 相应结构化字段非空 |
| `回复中包含“暂停”` | 助手正文包含字面子串 |
| `回复中不包含“播放失败”` | 正文不含该子串 |
| `回复中包含“暂停”或“停止”` | 两者至少包含一个（OR） |
| `回复中包含“杭州”和“天气”` | 两者都包含（AND） |
| `title是“灵犀服务”` | 业务标题等于指定值 |
| `title包含“外卖”` | 业务标题包含指定值 |
| `skillId是“VIDEO123”` | 真实业务 skillId 精确匹配 |
| `sdk.package是“com.example.app”` | 实际 SDK 包名等于指定值 |
| `deeplink以“cmcc://example”开头` | 真实 deeplink 字段前缀匹配 |

**匹配只看字面**：“无法暂停播放”包含“暂停”，因此上述“包含暂停”规则会通过，但并不表示暂停成功。“已停止当前视频”没有“暂停”，需要明确写成“暂停”或“停止”才能接受两种文案。

## 多条件组合

- `和`、`且`、`并且`、`以及`、`与`、`、`：全部满足。
- `或`、`或者`、`或是`：满足任意一项。
- 支持中文/英文括号：`回复中包含“杭州”和（“天气”或“气温”）`。
- 相邻引号中的多个词表示 AND：`文本回复包含“新闻联播”“CCTV1”`。
- 不同规则用 `/`、中文分号或换行分隔；分隔符在引号内时属于字段值，不应拆分。
- 可使用受支持的 JSON 表达式指定 `all`、`any`、`not`、`same_frame` 等严格结构条件。

## 字段与证据限制

- 标题、追问和 skillId 必须来自真实助手业务字段；正文中提到 ID 不能替代 skillId。
- 同帧视频 `code=4145` 控制需要相应 header/body skillId 一致；多个字段要求在同一帧同时成立时应使用 `same_frame`。
- `HTTP 200`、正常 SSE JSON 帧与所需 `[DONE]` 是不同校验层，不能因为命中关键词跳过协议检查。
- 不支持的宽泛语义要求（如“意图正确”“理解准确”“执行成功”而没有客观字段）在发起请求前应报错，不能默认通过。
- 不把原表“响应结果”列、用户发送的语料或顶层 reqId 当成业务响应参与判断。
