# 飞书群监控卡片自动分页｜v1.12.0

## 发送逻辑

本 Skill 默认优先一张 Card JSON 2.0。单卡容纳全部失败时仍只有一次 webhook 调用；超过大小上限时，自动按顺序分页为 1/N、2/N……。每页保留五指标、来源链接、按原顺序切分的 FAIL/ERROR 用例编号、场景和压缩原因；同一用例不遗漏、不重复。

正式拨测默认向私有配置中已授权的目标群发送；公开模板 `feishu.enabled=true`，首次运行须先配置该群的 Webhook/签名，否则业务 POST 前报错。仅用户明确要求测试不发通知时加 `--no-feishu`；`--check` 始终不发业务 POST 或群消息。

本地先构建并检验**所有分页**的合法性和大小，成功后才发送第一张。每页卡片 JSON 预算 18,000 字节，为签名封装保留余量（整体请求上限 20,000 字节）；单个编号或单页无法满足预算时，零消息发送并报 card_capacity_exceeded/card_render_failed。

### 发送结果

- 所有页发送成功：小批次保持传统返回值 sent；多页返回 status=sent、cards_total、cards_confirmed、cards_attempted。
- 第 N 页被明确拒绝或回执不确定：立即停止后续页，返回 cards_total、cards_confirmed、cards_attempted、failed_page、failed_page_outcome（rejected/uncertain），自动重试为 false。已确认页数不等于飞书客户端实际可见的页数。
- 默认页间等待 1 秒，避免过快触发群机器人频率限制；不做自动重发、跳页或假定超时后未投递。需要补发时应核对群消息和失败页，再明确审批操作。
- legacy 格式可能省略错误编号，依然拒绝；v2 和 auto 都沿用同一个分页路径，不因 schema 拒绝而自动降级重试。

任何卡片及共享输出均不含设备 ID、测试语料、完整原始 SSE、响应摘录、认证头、Token、Webhook 或 reqId；只共享经安全清洗的失败摘要。腾讯文档链接只保留可信 ID 和 tab，不含敏感查询串。首次真实拨测前须将获授权目标群及其可见范围写入私有配置。

## 历史报告

python3 scripts/share_report.py --report latest 默认只读检查历史 JSON v5/v6，并返回本轮需要的 group_cards，不发送飞书或业务 POST。仅在明确授权后运行 python3 scripts/share_report.py --report latest --send，按与预检完全一致的规则逐页发送，途中失败即停；不能因为曾经的回执不确定而盲目整批补发。

## 验收范围

- 0 失败：只有一张总览卡；总量为 0 的异常不能误报全部通过。
- 42 条失败：单卡发送，完整编号、五指标、来源链接及隐私保护不变。
- 超过单卡上限的批次：多页，每页标明 i/N；所有编号顺序完整且出现恰好一次，每页请求体均不超过 20,000 字节。
- 第二页被拒绝或网络结果不确定：记录此前确认送达页数，只尝试到第二页，不再发送后续页。
- 历史报告的干跑预检精确报告分页数，发送需要独立审批；仅使用模拟 webhook 和虚构语料执行开发回归，生产群可见效果需要授权成员另行验收。
