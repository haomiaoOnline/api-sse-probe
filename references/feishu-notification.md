# 飞书通知与云端归档

飞书通知是**可选的授权输出**，与本地报告存储相互独立。默认模板启用群通知，但没有真实 Webhook/签名，正式运行前必须先配置自己的目标群。

## 发送流程

1. 运行完成后，由本地私有报告生成脱敏摘要及失败清单。
2. 优先生成单张 Card 2.0；超过安全容量时先完整预检分页，再依次按 `1/N`、`2/N` 发送。
3. 任意页失败或投递结果不确定，立即停止，记录实际确认页数；**不自动重发**，避免重复消息。
4. 可选飞书云文档归档必须有授权的应用身份、指定文件夹和只读权限。先创建归档并完成回读、权限验证，再把受控链接放入群卡片。
5. UNKNOWN/PENDING 未结束的运行只能发送标注为“未完成”的报告，绝不称为全部通过。

## 安全约束

- 群消息只包含摘要、失败编号和经过核验的云文档链接；不能包含私有 Header、Token、设备 ID 或未脱敏 SSE。
- 云端归档也必须脱敏；完整原始字节和凭据只在私有运行目录中。
- `--check` 不发群消息；明确要求不通知时使用 `--no-feishu`（也禁止该次云归档）。
- 对异常通知只能核对回执；如果发送结果未知，不得自动重发。

## 维护入口

- 群消息：`scripts/lib/feishu_notification_router.py`、`feishu_transport.py`
- 报告归档：`scripts/lib/feishu_archive.py`
- 历史报告手动补发：`python3 scripts/share_report.py --report latest`（只读预检）；必须另行授权 `--send`
